# Day 1: SDLC Fundamentals - Today's Tasks

## 1. Define SDLC
**Task:** Write your own definition of the software development life cycle in 3–5 sentences.
**Answer:** 
Sdlc is the process used to build and maintain software. it covers everything from planning and design to development, testing, deployment, and maintenance. Its main goal is to deliver a reliable product that meets requirements efficiently.

## 2. List Core Phases
**Task:** Identify common phases (requirements, design, implementation, testing, deployment, maintenance).
**Answer:**
- **Requirements:** Determining exactly what the software needs to do and identifying stakeholder needs.
- **Design:** Planning the application architecture, database schemas, and user interface.
- **Implementation:** Writing the code while adhering to the established design and architecture.
- **Testing:** Debugging the software and verifying that it successfully meets all the defined requirements.
- **Deployment:** Releasing the working, tested software to servers or app stores, making it accessible to end-users.
- **Maintenance:** Monitoring the live application, improving performance, fixing minor bugs, and keeping it updated by adding new features over time.

## 4. Why It Matters
**Task:** Note 3 risks of skipping a phase (e.g., building without requirements).
**Answer:**
1. **Building the Wrong Product:** Skipping the "Requirements" phase and jumping straight into coding often results in building a product that users don't actually need, leading to a massive waste of time and resources.
2. **Spaghetti Code and Lack of Scalability:** Skipping the "Design" phase leads to an unplanned, messy application architecture. This makes it extremely difficult and costly to add new features or scale the system in the future.
3. **Critical Crashes in Production:** Rushing or entirely skipping the "Testing" phase causes the application to crash in the hands of end-users, which leads to security vulnerabilities and a severe loss of reputation.
